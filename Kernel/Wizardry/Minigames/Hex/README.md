# Hex (CONFIG_HEX_CARDS)

Hex card game port. The switch is `CONFIG_HEX_CARDS` in `include/configs/configs.h`.

The Hex row in the preparations menu can be hidden at runtime with `prep_menu_hex` in `Data/DesignerConfig/designer-config.c` (default `true`).

- `Source/HexCore.c`: rules engine and AI (`include/kernel/hex-core.h`). No game globals, no `/` or `%`.
- `Source/HexCards.c`: the card item helpers, the binder helpers (`HexCol_*`), the item migration and the starter gift
  (`include/kernel/hex.h`). Card table: `Data/Hex/HexCardTypes.c` (44 types, `HEX_CARD_TYPES`).
- `Source/HexSave.c`: the card binder, `gHexSave` (`struct HexSaveData`, 0x54 bytes: magic, `binder[48]` copies per type,
  `claims[32]` district claim counters). It is one chunk in each save list (`EmsChunk($0054, HexSave_Save, HexSave_Load)` in
  `Kernel/Wizardry/SaveData/data.event`, game and suspend), and `HexSave_NewGame` clears it on a new game. The limit is
  `HEX_BINDER_MAX` (255) copies per type. A save made before the chunk existed loads an empty binder.
- `Source/HexDistrict.c`: the district matches (`StartDistrictHexASMC`, the NPC decks in `Data/Hex/HexNpcDecks.c`) and the rows
  and payment of the district shops (`HexShop_Get`, `HexShop_CanAfford`, `HexShop_Pay`; the rows are in `Data/Hex/HexShops.c`).
  See `Documentation/Features/Districts.md`.
- `Source/HexShopVanilla.c`: the district Hex shop. `StartDistrictHexShopASMC`, called by the door's location event, opens the
  vanilla shop screen (`StartShopScreen`) with `shopType` `SHOP_TYPE_HEX` (4, `include/kernel/hex.h`). `HexShop_IsActive` says
  whether the shop screen is in Hex mode.
  - In Hex mode the shop screen's portrait is the shopkeeper box witch, `FID_HEX_WITCH_SHOP` (0xAF). The lines are hers
    (`MSG_HEXSHOP_*`, in `Contents/Texts/Source/texts/Districts.txt`). The shop opens at the buy list.
  - Four vanilla functions are replaced (`LYN_REPLACE_CHECK`, redirected by `Source/LynJump.event`): `Shop_GetPortraitIndex`,
    `StartShopDialogue`, `Shop_EntryDialogue` and `Shop_AnythingElseRestartDialogue`. Each runs the Hex code in Hex mode and the
    vanilla code otherwise. `Shop_GetPortraitIndex` returns `FID_HEX_WITCH_SHOP` for the Hex shop.
  - The Hex branches in `Kernel/Wizardry/LimitedShopStock/src/LimitedShopStock.c` (`CONFIG_HEX_CARDS`) are: `DrawShopItemPriceLine`
    (`HexShop_DrawPriceLine`), `Shop_Loop_BuyKeyHandler` (`HexShop_OnBuyPressed`, and B), `HandleShopBuyAction`
    (`HexShop_PayForItem`: cards pay, no gold, no stock) and `Shop_Init` (no gold box).
  - `Shop_Init` still resets the system font and inits the gold text in Hex mode. Only the gold box is left out. The code comment
    says this gives the item texts the same tiles as a normal shop.
  - `gHexShopRam` (`struct HexShopRam`, 0x20 bytes, `include/link/config-memmap.s`) holds the wares of the open shop: up to 12
    item words and a 0 terminator. It is RAM only, not saved.
- Witch portrait: `FID_HEX_WITCH_SHOP` is portrait 0xAF (`include/kernel/hex.h`), the only Hex witch portrait. It is set by
  `setMugEntry(0xAF, ..., 4, 3, 3, 2)` in `Data/CustomPortraits/CustomPortraits.event` from
  `Data/CustomPortraits/Portraits/hex_witch_shop.png`, which `Tools/hex/witch_shop_from_art.py` makes from the supplied pixel-art
  illustration `Tools/hex/art/hex_witch_shop_source.webp`. The script reads the art's 64x64 pixel grid exactly, crops a 48x48
  window into the shopkeeper box, maps it to 15 fitted colours, adds three mouth frames, and stores the sheet mirrored because
  the shop draws the box flipped. The vanilla portraits end at 0xAC, so the portrait table is moved.
  `Data/CustomPortraits/PortraitTable.event` copies the vanilla table into `NewPortraitTable` with room for 0x100 entries.
  `Preload/AllocPortraitTable.event` defines `PortraitTable` as `NewPortraitTable` and `PORTRAIT_TABLE_ENTRIES` as 0x100.
- `Data/Hex/HexMonsterArt.c`: the 12 monster minimugs (`gHexMonsterArt`), used by `HexScreen_LoadType` for the card types
  `>= HEX_MONSTER_FIRST` (32) in place of the chibi. It is generated by `Tools/hex/gen_monster_mugs.py` from the FE8 monster class
  cards: `--check` verifies the output, `--preview PATH.png` writes a 4x preview. Do not edit it by hand.
- `Source/HexArt.c`: card art data. The UI tiles, digits, cursors and frame palettes are copied from the Minish Cap mod
  (`src_custom/hexUiArt.c` there). `gHexPortraitKeep` is generated by `Tools/hex/gen_hex_art.py`; rerun it (or `--check`) after
  any change to the hexagon geometry.
- Card art, back to front: the owner-coloured card back (`gHexCardBackTiles`), the chibi clipped to the hexagon interior (`gHexPortraitKeep`), then a thin 2 px red or blue ring with the reach dots (`gHexFrameTiles`, one per reach mask), then the digits.
- `Source/HexPrep.c`: entry point called from the prep menu (`AtMenu.c`, the "Hex" row).
- `Source/HexScreen.c`: the Hex screen (`ProcScr_HexScreen`): the front menu, the opponents, the collection viewer, the hand
  picker, the match, the stakes (see below). Both hands, both scores and the name bar.
  Portraits are the FE8 chibis, clipped to the hexagon by the keep mask (the monster minimugs for types 32 to 43).
- `Hex_Installer.event`: included from `Kernel/Wizardry/wizardry.event` under `CONFIG_HEX_CARDS`.
- Card icon: `Data/CustomItems/HexCard/Installer.event` (under `CONFIG_HEX_CARDS`) writes the 16x16 card picture to item icon slot `ITEM_ICON_HEX_CARD` (`0x8E`); the `0xEC` row in `Data/ItemSys/Source/Items.c` uses it.

The screen state is kept in `gHexScreenState` (`struct HexScreenState`, 0x280 bytes, `include/link/config-memmap.s`), not in the
proc: a proc is 0x6C bytes, and the proc holds only the name bar text, the saved display registers and the blue selection. The
state holds the list texts and a cached copy of the collection (owned types and copies, read once when the screen opens). Sprites
are pushed back to front (PutSprite draws a later call in front). The layers are set once on open (BG0 text, BG1 windows, BG3
mural, OBJ) and the screen does not rewrite them every frame.

## Look

The screen uses the same layout as the other preparations sub-screens (`PrepItemList_InitGfx_INFUSE`, the Infuse screen): the
rune mural on BG3 (`RestartMuralBackground`, ended by `EndMuralBackground_` on exit), the standard game windows on BG1
(`DrawUiFrame2`, style 0), and the text on BG0 over them. There is no wood and no flat plate.

- The list window (MENU, OPPONENT, CARDS, HAND_PICK, PICK_DONE) is over the board area: tiles x 5..24, y 0..15. The title is on
  row 1 and the six list rows on rows 3, 5, ..., 13, so the list sits inside the border. Its cursor (a right arrow, pointing at the
  names) and the preview card at the right are drawn on it.
- The name bar is a window across the bottom, tiles x 5..24, y 16..19, with the text on row 17 (inside the frame), centred. It is narrower than the
  screen because the hands (red x 4..36 on the left, blue x 204..236 on the right) sit at the sides: a longer line can be partly covered by a
  card.
- Both windows are redrawn when their content changes (the list on every list-state change, the bar whenever its text changes).
  In the match states only the bar window is shown, and the board and hands sit on the mural.

## Front menu, opponents and cards

The screen opens in MENU: the title "Hex" and two rows, "Play" and "Cards". UP / DOWN choose a row, A opens it, B leaves for the
prep menu (the Hex row is kept selected there). `HexScreen_Init` first runs `HexCol_MigrateItems` (Hex Card items in the convoy
and the living units' inventories go into the binder), then `HexCol_GiveStarters` hands out the starter set when the binder is
empty. MENU is also where the screen returns after every match (after the REWARD banner), except in district mode (below).

### Opponents (OPPONENT, from Play)

The list shows the living units of the player's army (the same units the card count reads: `gUnitArrayBlue`, not dead), in array
order, six rows at a time. Each row has the unit's name and "Lv N" (its level) on the right. As the cursor moves, the red column
shows that unit's deck face up, and the name bar shows "<Name>'s deck". UP / DOWN move the cursor (held keys repeat), A starts the
hand picker against the highlighted unit's deck and AI level, B goes back to MENU. With no living unit, A does nothing.

The deck and the strength come from the unit only (`HexScreen_SetOpponent`, `HexScreen_MakeDeck`), so the same unit at the same
level and promotion always gets the same deck. Let `eff` be the unit's level, plus 20 if the unit is promoted (`CA_PROMOTED` in
its attributes):

- AI level (`Hex_AiChoose`): 1 if `eff` < 10, otherwise 2. Army opponents never play at level 0 (random moves); level 0 stays in
  the engine for the host tests.
- Card tier cap: 1 if `eff` < 10, 2 if `eff` < 20, otherwise 3.
- The first card is the card of the unit's own character (the card type whose pid is the unit's pid), when there is one, even above
  the tier cap.
- The other cards of the 7-card deck are drawn from the card types of tier <= the cap, with at most two copies of one type in the
  deck. Only the character types (0 to 31) are drawn: `HexScreen_MakeDeck` skips the monsters (`t < HEX_MONSTER_FIRST`).
  The draw is a u32 LCG seeded from the pid: `s = pid * 2654435761 + 12345`, and each draw does `s = s * 1103515245 + 12345`
  and takes the index `(s >> 16) mod n` over the `n` eligible types, in table order. The mod is done by repeated subtraction: the
  game's unsigned divide-with-remainder routine (`__aeabi_uidivmod`) returns the remainder in the wrong register on this build.

A unit that gains a level (or is promoted) can get a different deck and AI level the next time it is chosen.

### Cards (CARDS, from Cards)

The title is "Cards  N/44": N is the number of card types owned at least once, out of 44 (`HEX_CARD_TYPES`). The rows are all 44
types in table order, six at a time, scrolling. An owned type shows its card's name (the character, or the class for a monster)
and the copies in the binder (`HexCol_Count`). A type never owned shows "???" with no count. The preview at the right shows the
highlighted card (its portrait and stats) if it is owned, and the name bar shows its tier ("Tier 1", "Tier 2" or "Tier 3"), blank
for "???". The red and blue columns are empty. B goes back to MENU.

### District mode

The screen is started from a district map (`Source/HexDistrict.c`, see `Documentation/Features/Districts.md`). It runs as a
child of the map's `HexDistrict` proc, which suspends the map display while the screen runs. `HexScreen_OnEnd` hands back
to the prep menu only in the prep case (no NPC deck).

- **District match** (`StartDistrictHexASMC`): the talk event puts the NPC's character id in `gEventSlots[2]`, and
  `HexScreen_SetDistrictDeck` sets the NPC's row in `gHexNpcDecks`. The screen opens in HAND_PICK against that deck
  (`HexScreen_SetNpcOpponent`: the name, the AI level, and a rare card the NPC has run out of is its fallback). MENU and OPPONENT
  are skipped: B with no card in hand, and the end of the stakes, leave the screen. A win takes a card with `HexCol_Give`, and a
  rare card of the deck adds a claim (`HexClaim_Add`). A loss takes a random card of the hand played (`NextRN_N`).

The district shop is not part of this screen. It is `Source/HexShopVanilla.c` (above).

## Match

The screen has three parts: the hand picker, one match, and the stakes. The hand picker is entered from OPPONENT, or at once in
district mode (above).

### Hand picker (HAND_PICK, PICK_DONE, REVEAL)

HAND_PICK is entered from OPPONENT (or at the start of a district match). The board is not drawn: the middle of the screen holds a list of the card types the player owns
(copies in the binder), in type order, with a "Your cards" title. Each row shows the
name and the copies still available (owned minus the ones already picked), right-aligned; six rows show at a time and the list
scrolls. The blue column (right) shows the cards picked so far, top down; the red column (left) is the opponent's hand, face up.
The highlighted card is previewed at the right of the list, and the name bar shows its name.

- UP / DOWN (held keys repeat): move the list cursor.
- A: add a copy of the highlighted type (error sound if none is left, or the art has no bank).
- B: remove the last card. With no card in hand, B goes back to OPPONENT (no match, no penalty). In district mode that leaves the screen.
- At 7 cards: PICK_DONE, with "Accept" and "Change" on the list rows. UP / DOWN choose, A confirms. Change, or B, removes the last
  card and goes back to HAND_PICK.
- Accept: REVEAL. The opponent's hand is shown with "Your opponent's hand" for 60 frames (A skips), then BEGIN.

The opponent's hand is the deck of the chosen unit, played at that unit's AI level (`redHand`, `aiLevel` in the state; see
Opponents). The first player is chosen from the game clock.

### Match (BEGIN, PICK_TILE, PICK_CELL, RESOLVE, AI_TURN, END)

The match ends when the board is full. Red's moves come from `Hex_AiChoose`.

- BEGIN: "Blue begins" or "<Name> begins" (the opponent's name) in the name bar for 60 frames (A skips it).
- PICK_TILE: a right arrow just left of the highlighted blue card, pointing at it; the name bar shows its name. UP/DOWN step over unused cards.
  A goes to PICK_CELL. B does nothing: a match is played to its end.
- PICK_CELL: a down arrow on the top edge of the cell (the same place in every cell), the highlighted card stays marked. D-pad moves to a neighbour (UP: UL or UR, DOWN: DL or
  DR, LEFT/RIGHT: L or R; an empty neighbour is preferred), or to the cell before/after in reading order when there is none.
  A places the card (an occupied or illegal cell plays the error sound). B goes back to PICK_TILE.
- RESOLVE: 66 frames (`HEX_RESOLVE_FRAMES` = 30 + 16 + 20); the name bar shows the card just placed. For the first 30 frames
  (`HEX_ATTACK_DELAY`) the board and both scores are the ones from before the placement (`shownCell`, `shownScore`), with the placed
  card on its cell at full HP. At frame 30 the attack shows: the flipped cells in their new colour, the lost HP, and a hit sound
  (`HEX_SE_HIT` = 0xD4, the battle hit sound: the first id of `EfxPlayHittedSFX`) if anything changed. For 16 frames from there
  (`sHexShake`) the cards that lost HP, changed owner, or (the placed card) were counterattacked shake sideways. Then 20 frames of
  the settled board. The hands always show the real state (the card has left the hand at once).
- AI_TURN: "<Name> is thinking" for one frame, then the opponent places.
- END: "Victory!", "Defeat..." or "Draw" in the name bar. A decides the stakes (below).

### Stakes (END, TAKE, REWARD)

- Win (blue): if the player holds fewer than 255 copies (`HEX_BINDER_MAX`) of at least one type in the red hand, TAKE
  (`HexScreen_Takeable`); otherwise REWARD with no card gained. TAKE: the cursor is on the red column (left), a left arrow just
  right of the card, UP/DOWN choose one of the opponent's 7 starting cards, and A puts it in the binder (`HexCol_Give`). A type the
  player already holds 255 of is refused: error sound and "You can't hold more" for 60 frames. There is no convoy check for cards.
- Loss (red): if the player owns more than 7 cards (`HexCol_Total`), one card is taken from the hand just played (`HexCol_TakeOne`).
  Against a district NPC it is a random card of that hand (`NextRN_N`). In the prep menu it is the best card: highest tier, then
  the highest attack + max HP; the first in hand order on a tie (`HexScreen_HighestPick`). Otherwise "Your cards are safe this time."
- Draw: "Draw. No cards change hands."
- REWARD: "Gained <card>!" or "Lost <card>..." (or one of the messages above) for 120 frames, or until A. The screen then goes back
  to MENU (B there leaves for the prep menu).

Sounds: cursor moves `SONG_SE_SYS_CURSOR_UD1` / `SONG_SE_SYS_CURSOR_LR1`, select (place, pick, accept, A at END and REWARD)
`SONG_SE_SYS_WINDOW_SELECT1`, cancel (B) `SONG_SE_SYS_WINDOW_CANSEL1`, error `SONG_6C` (the ones the prep menu uses).

Not in this part: the flashing of the flipped cells.

## Toggling CONFIG_HEX_CARDS in a cloud session

`Tools/cloud/build.sh` does not regenerate tracked `.lyn.event` files whose `.c` is unchanged in git. So after turning the switch on or off, the `.lyn.event` outputs of the guarded `.c` files keep their old content and the build fails (for example `DuraItem.lyn.event:33:6 Undefined identifier: HexCard_NameId` when the switch is off).

Delete the guarded outputs, then build:

```
rm -f Data/ItemSys/Source/Items.lyn.event \
  Kernel/Wizardry/ItemSys/ItemInfoRemap/Source/DuraItem.lyn.event \
  Kernel/Wizardry/ItemSys/ItemInfoRemap/Source/ItemInfos.lyn.event \
  Kernel/Wizardry/SkillEffects/MenuSkills/Reinforce.lyn.event \
  Kernel/Wizardry/SkillSys/PrepSkill/Source/AtMenu.lyn.event \
  Data/Hex/HexCardTypes.lyn.event \
  Data/Hex/HexNpcDecks.lyn.event \
  Data/Hex/HexShops.lyn.event \
  Data/Hex/HexMonsterArt.lyn.event
Tools/cloud/build.sh
```

`build.sh` regenerates them because a missing file is not protected. Afterwards, `git diff` on those files should show only the expected changes for this feature (AtMenu.lyn.event). Do not change `build.sh` for this.
