# Pre-phase skills

> Text file: `Contents/Texts/Source/texts/Skills_PrePhase.txt`  ·  Code: `Kernel/Wizardry/SkillEffects/PrePhaseSkills/`  ·  Hook: `gPrePhaseFuncs` in `Kernel/Wizardry/PrePhaseHook/data.event`

## What it is

Entries in `gPrePhaseFuncs` run when a faction's phase starts, before the player can act. They read the phase's units (`gPlaySt.faction`) and usually set or clear temporary stat debuffs/buffs on units (`SetUnitStatDebuff` / `ClearUnitStatDebuff`). A few start a blocking anim or change faction, tiles, MP or HP at phase start.

## How the engine calls it

1. The PrePhase hook is installed in `gProc_BMapMain` at `Kernel/Wizardry/PrePhaseHook/PrePhaseHook.event:7-8` (`ORG 0x59A2C0`, `PROC_CALL_ROUTINE_2(PrePhaseHook)`). `PROTECT` for `gProc_BMapMain` is on `:10`.
2. `PrePhaseHook(ProcPtr proc)` (`Kernel/Wizardry/PrePhaseHook/Source/PrePhaseHook.c:15-19`) calls `KernelStartBlockingHookProc(gPrePhaseFuncs, proc)` and returns `false`.
3. `KernelStartBlockingHookProc` (`Kernel/Wizardry/KernelLib/Source/hook-proc.c:84-93`) and `HookProc_Main` (`hook-proc.c:52-68`) walk the list. Entry type is `bool (*)(ProcPtr)` (`include/common-chax.h:44`). `false` continues in the same frame. `true` stops for the frame and resumes next frame (`hook-proc.c:64-66`, `:70-82`).
4. List (`Kernel/Wizardry/PrePhaseHook/data.event:3-37`). Tick entries come first (`:7-13`), then misc and apply entries (`:14-31`). The end block (`:33-37`) is `// End`, `PrePhase_HellscapeTrapDecay`, `CallExternalPrePhaseHook`, `PrePhaseHook_VanillaEnd`, and `WORD 0 0 0 0 0`.
5. `PrePhaseHook_VanillaEnd` (`PrePhaseHook.c:9-13`) starts `gProcScr_GorgonEggHatchDisplay` and returns `true`.

Faction: `gPlaySt.faction` is the faction whose units are being processed. Skills loop over it with `FOR_UNITS_ONMAP_FACTION` (`include/kernel/kernel-lib.h:417`), which expands to `FOR_UNITS_ONMAP` (`:403-415`). That macro skips units where `UnitOnMapAvaliable` is false. Inferred from usage, not traced in the engine: `gPlaySt.faction` is the phase that is starting.

Temporary status: `SetUnitStatDebuff` sets a bit in the unit's status bitmask (`Kernel/Wizardry/DebuffRework/StatDebuff/StatDebuff.c:125-137`). Bits are cleared by `TickUnitStatDebuff(unit, tick_type)` (`StatDebuff.c:248-263`), called from `TickActiveFactionTurn` (`Kernel/Wizardry/DebuffRework/Source/StatusDepletion.c:26`). In the blue-faction branch, `:87` ticks `STATUS_DEBUFF_TICK_ON_ALLY` for blue units and `:110` ticks `STATUS_DEBUFF_TICK_ON_ENEMY` for red units. The other faction branches mirror this later in the file. The tick type comes from the table entry (`Data/Debuff/StatDebuffInfo.c:430`, `[UNIT_STAT_BUFF_KEEPUP]` is `STATUS_DEBUFF_TICK_ON_ALLY`). The caller of `TickActiveFactionTurn` is not traced here (unverified).

## Add one: steps

1. Do the common steps in [Common.md](Common.md).
2. Create `Kernel/Wizardry/SkillEffects/PrePhaseSkills/<Name>.c` with a non-static `bool PrePhase_<Name>(ProcPtr proc)`. Return `false` unless you started a blocking proc. Non-static is required because `data.event` references the symbol. The list type is `bool` (`PrePhaseHook/data.event:1`).
3. Pick the pattern:
   - State only (set or clear a debuff for each unit): loop with `FOR_UNITS_ONMAP_FACTION(gPlaySt.faction, unit, { ... })`. See `KeepUp.c`.
   - Blocking anim: `Proc_StartBlocking(ProcScr_<X>, proc); return true;`. See `ChillSkills.c:290-293`.
4. For a new temporary status:
   - Add an entry to `enum UNIT_STAT_DEBUFF_IDX` in `include/kernel/debuff.h`. The enum runs to `UNIT_STAT_DEBUFF_MAX_REAL` at `:303`. Check there is room below `UNIT_STAT_DEBUFF_MAX` (`:304`, the comment says do not modify it).
   - Add a table entry `[UNIT_STAT_BUFF_<X>] = { .positive_type = ..., .tick_type = ..., .unit_status = {...} }` in `Data/Debuff/StatDebuffInfo.c`. Pick the `tick_type` to match the turn that should clear it (see "How the engine calls it").
   - Set it from your pre-phase function with `SetUnitStatDebuff`.
   - If you need to clear it yourself, use `ClearUnitStatDebuff`, as `Initiative.c:104-114` does.
5. Register: add `    POIN PrePhase_<Name>` to `gPrePhaseFuncs` in `Kernel/Wizardry/PrePhaseHook/data.event`, above the `// End` comment (`:33`). Entries after `PrePhaseHook_VanillaEnd` run after the Gorgon egg display proc has started (`PrePhaseHook.c:11`). For tick/clear-type functions, the existing order puts them near the top (`:7-13`). That ordering rationale is not documented (unverified).
6. Include: add `#include "PrePhaseSkills/<Name>.lyn.event"` to the PrePhase block in `Kernel/Wizardry/SkillEffects/MiscSkillEffects.event` (around `:139-159`).
7. Build and test. Not covered by this doc.

## Template

Adapted from `Kernel/Wizardry/SkillEffects/PrePhaseSkills/KeepUp.c` (`PrePhase_TickKeepUpSkillStatus`, `:13-59`), using only the per-unit loop and `SkillTester` pattern.

```c
#include "common-chax.h"
#include "debuff.h"
#include "kernel-lib.h"
#include "skill-system.h"
#include "constants/skills.h"

bool PrePhase_Example(ProcPtr proc)
{
	FOR_UNITS_ONMAP_FACTION(gPlaySt.faction, unit, {
		if (unit->state & (US_HIDDEN | US_DEAD | US_RESCUED | US_BIT16))
			continue;

#if defined(SID_Example) && (COMMON_SKILL_VALID(SID_Example))
		if (SkillTester(unit, SID_Example))
			SetUnitStatDebuff(unit, UNIT_STAT_BUFF_EXAMPLE);	/* placeholder: add this enum entry and table entry first */
#endif
	})

	return false;
}
```

Registration, in `Kernel/Wizardry/PrePhaseHook/data.event`, inside `gPrePhaseFuncs` above `// End`:

```
    POIN PrePhase_Example
```

Registration, in `Kernel/Wizardry/SkillEffects/MiscSkillEffects.event`, in the PrePhase block:

```
#include "PrePhaseSkills/Example.lyn.event"
```

## Worked examples

- `Kernel/Wizardry/SkillEffects/PrePhaseSkills/KeepUp.c` : `PrePhase_TickKeepUpSkillStatus` (`:13`). Owner-buff pattern: loop over the faction, check a 3x3 neighbour for an allied unit with a skill, then call `SetUnitStatDebuff` on the owner (`:56`).
- `Kernel/Wizardry/SkillEffects/PrePhaseSkills/HoneFortify.c` : `PrePhaseFunc_HoneFortify` (`:9`). Same faction loop. Applies stat buffs to allies in a 2x2 area (`gVecs_2x2`, `:160-161`, `:172-203`) and checks class with `CheckClassCavalry` / `CheckClassFlier` / `CheckClassArmor`.
- `Kernel/Wizardry/SkillEffects/PrePhaseSkills/ChillSkills.c` : `PrePhaseFunc_Chill` (`:290-294`) starts `ProcScr_PrePhaseChill` with `Proc_StartBlocking(..., proc)` and returns `true`. The Chill debuffs are cleared in a post-action entry, `PostAction_RemoveChillDebuff` (`:296`), which is the clear side of this pair.
- `Kernel/Wizardry/SkillEffects/ChapterInitSkills/Initiative.c` : `PrePhase_TickInitativeSkillStatus` (`:134-168`). Explicit clear, not a re-apply. Clears the Initiative debuffs when `gPlaySt.chapterTurnNumber >= 2` in the blue phase, unless `SID_EternalVanity` is held (`:139-164`). This file is also used for chapter init (see the End-turn doc).

## Gotchas

- `PrePhase_Tick*` is a naming convention, not a counter decrement. `PrePhase_TickKeepUpSkillStatus` re-applies its debuff every phase (`KeepUp.c:56`). Debuff bits are removed only by `TickUnitStatDebuff` (`StatDebuff.c:248-263`), matched by `tick_type`. Status duration counting is a separate mechanism and is not covered here.
- KeepUp: `_SetKeepUpStatDebuff(unit)` (`KeepUp.c:56`) sets the debuff on the outer `unit`, the one that has `SID_KeepUp`. The ally is only checked (`:39-55`). Verify this is the intended target before copying the pattern.
- Several entries are declared `void` but sit in the `bool` table (`HookProcFunc_t`): `PrePhaseMisc.c:12` (`PrePhase_ResetFaction`, data.event `:14`), `PrePhaseMisc.c:75` (`PrePhase_ApplyMpStartingAmount`, `:19`), `PrePhase_LaguzBars.c:11` (`:17`), `Truant.c:5` (`:31`). Their return register is undefined, and the runner stops the list on any non-zero value (`hook-proc.c:64-66`). Unverified whether this causes a visible problem. New entries should be `bool` and return `false`.
- The phase's unit loops filter with `UnitOnMapAvaliable` (`kernel-lib.h:403-415`). Units with `US_HIDDEN`, `US_DEAD`, `US_RESCUED`, `US_BIT16` are skipped by the skill loops themselves (`KeepUp.c:20-21`, `HoneFortify.c:27-28`). Keep that check if you add a loop.
- `FOR_UNITS_ONMAP_ALL` covers every allegiance, not just the current faction (`kernel-lib.h:423-438`). Use `FOR_UNITS_ONMAP_FACTION` for a per-phase loop.
- `PrePhase_TickInitativeSkillStatus` (`Initiative.c:134-168`) has an unusual brace layout around the two loops. Read it before copying it. The `KeepUp.c` loop is the cleaner model.
- The PrePhase hook is called from `gProc_BMapMain` (`PrePhaseHook.event:7-10`). The exact per-phase timing and whether it runs once or once per faction were not traced (unverified).
