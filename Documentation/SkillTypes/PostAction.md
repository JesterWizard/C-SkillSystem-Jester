# Post-action skills

> Text file: `Contents/Texts/Source/texts/Skills_PostAction.txt`  ·  Code: `Kernel/Wizardry/SkillEffects/PostActionSkills/`  ·  Hook: `gPostActionFuncs` in `Kernel/Wizardry/PostActionHook/data.event`

## What it is

Entries in `gPostActionFuncs` run after a unit's action has resolved (combat, staff, item, wait, rescue), in both the player phase and the CPU phase. They read the finished action and can start a map anim, popup or event, or change unit state (refrain the action, set or clear debuffs, grant gold or items, place tiles, revive units).

## How the engine calls it

1. The vanilla player-phase and CPU-perform proc scripts are redirected at `Kernel/Wizardry/PostActionHook/PostActionHook.event:11-12` (`ORG $59ABE0`, `PROC_JUMP(ProcScr_PostActionHookPlayPhase)`) and `:15-16` (`ORG $5A8074`, `PROC_JUMP(ProcScr_PostActionHookCpPerform)`). Each script runs `PROC_YIELD`, `PROC_CALL(PostActionHook)`, `PROC_YIELD`, then jumps back into vanilla at `0x0859ABE8` / `0x085A807C` (`Kernel/Wizardry/PostActionHook/source/PostActionHook.c:31-45`).
2. `PostActionHook(ProcPtr proc)` (`Kernel/Wizardry/PostActionHook/source/PostActionHook.c:7-10`) calls `KernelStartBlockingHookProc(gpPostActionFuncs, proc)`.
3. `KernelStartBlockingHookProc` (`Kernel/Wizardry/KernelLib/Source/hook-proc.c:84-93`) starts a blocking `HookProc` under `proc` with index 0, plus the START-key listener.
4. `HookProc_Main` (`hook-proc.c:52-68`) calls the list entries in order. Each entry is `HookProcFunc_t` = `bool (*)(ProcPtr)` (`include/common-chax.h:44`).
   - Returns `false`: the next entry runs in the same frame.
   - Returns `true`: the walk stops for this frame. The proc yields (`hook-proc.c:70-82`) and resumes at the next entry on the next frame.
   - A `0` word ends the list and the proc goes to label 2 (`hook-proc.c:58-61`).
5. List order (`Kernel/Wizardry/PostActionHook/data.event:3-50`): `PostAction_CommonStart` first (`:4`; `Kernel/Wizardry/PostActionHook/source/usr-func.c:5-29` fills `gPostActionCommonBuffer` with total damage dealt and taken), then the skill entries (`:5-44`), then the end block (`:46-50`: `CallExternalPostActionHook`, pad entries, `ClearBattleGlobalFlags`, `PostActionEnd`). `PostActionEnd` (`source/PostActionHook.c:12-23`) calls `ResetCombatArtStatus`, `ResetSkillLists`, `ResetCombatArtList`, `HandlePostActionTraps`, then returns true.

Blocking: a `true` return is meant for a child proc started with `Proc_StartBlocking(child, parent)`, where `parent` is the hook argument. The helpers that take `parent` do this:
- `CallMapAnim_HealExt` (`Kernel/Wizardry/MapAnims/Misc/Heal.c:80-92`)
- `NewMuSkillAnimOnActiveUnitWithDeamon` (`Kernel/Wizardry/SkillSys/SkillMapAnim/MapAnimSkillMini.c:227-231`): starts the anim on `PROC_TREE_3`, then a blocking deamon proc on `parent` that waits while `MuSkillAnimExists`
- `KernelCallEvent` (`Kernel/Wizardry/KernelLib/Source/event-call.c:24-36`)

`Proc_StartBlocking` is declared at `Tools/FE-CLib-Mokha/include/proc.h:137`. How the engine's proc runner resumes the parent when the child ends is not traced here (unverified).

## Add one: steps

1. Do the common steps in [Common.md](Common.md).
2. Create `Kernel/Wizardry/SkillEffects/PostActionSkills/<Name>.c` with a non-static `bool PostAction_<Name>(ProcPtr parent)`. It must be non-static because `data.event` references it by symbol. Every entry in `data.event` is a non-static function (for example `Glorifier.c:8`).
3. Check the finished action. Fields that existing skills read:
   - `gActiveUnit`: the acting unit (`Glorifier.c:10`, `Tsuzuku.c:55`)
   - `gActionData.unitActionType`: `UNIT_ACTION_COMBAT`, `UNIT_ACTION_WAIT`, `UNIT_ACTION_STAFF`, `UNIT_ACTION_USE_ITEM`, `UNIT_ACTION_RESCUE` (switch in `Kernel/Wizardry/SkillEffects/PostActionSkills/Tsuzuku.c:129-352`). Also `CONFIG_UNIT_ACTION_EXPA_GaidenMagicCombat` / `...Staff` (`Glorifier.c:13-16`)
   - `gActionData.targetIndex`: the target, via `GetUnit(...)` (`Caltrops.c:9`, `Heal.c:108`)
   - `gBattleActorGlobalFlag.enemy_defeated`, `.hitted` (`include/kernel/battle-system.h:96-117`)
   - `gBattleActor`, `gBattleTarget` (battle-side units, `Tsuzuku.c:240`)
   - `gPostActionCommonBuffer.total_damage_actor` / `total_damage_target` (`include/kernel/post-action.h:8-10`)
4. Gate the unit: `UnitAvaliable(gActiveUnit)` and `UNIT_STONED(gActiveUnit)` (`Heal.c:18`, `Glorifier.c:24`; `UNIT_STONED` is declared at `include/kernel/debuff.h:16`).
5. Test the skill with `SkillListTester(unit, SID_<Name>)` (`Glorifier.c:24`), guarded by `COMMON_SKILL_VALID`.
6. Apply the effect. If you start an anim, pass `parent` to the helper and return `true`. If nothing was started, return `false`.
7. Register the function: add `    POIN PostAction_<Name>` to `gPostActionFuncs` in `Kernel/Wizardry/PostActionHook/data.event`, above the `//End` comment (`:46`).
8. Include the generated file: add `#include "PostActionSkills/<Name>.lyn.event"` to the PostAction block at the top of `Kernel/Wizardry/SkillEffects/MiscSkillEffects.event`.
9. Build and test. Not covered by this doc.

## Template

Adapted from `Kernel/Wizardry/SkillEffects/PostActionSkills/Glorifier.c` (`:8-35`). The START-skip logic is from `Heal.c:125-131`.

```c
#include "common-chax.h"
#include "skill-system.h"
#include "debuff.h"
#include "kernel-lib.h"
#include "battle-system.h"
#include "constants/skills.h"

bool PostAction_Example(ProcPtr parent)
{
#if defined(SID_Example) && (COMMON_SKILL_VALID(SID_Example))
	if (!UnitAvaliable(gActiveUnit) || UNIT_STONED(gActiveUnit))
		return false;

	switch (gActionData.unitActionType) {
	case UNIT_ACTION_COMBAT:
	case CONFIG_UNIT_ACTION_EXPA_GaidenMagicCombat:
		break;

	default:
		return false;
	}

	if (!SkillListTester(gActiveUnit, SID_Example))
		return false;

	if (!gBattleActorGlobalFlag.enemy_defeated)
		return false;

	/* Apply the effect here. It must run on both the anim and the skip path. */

	if (CheckKernelHookSkippingFlag())
		return false;	/* no proc started, so do not block the hook list */

	NewMuSkillAnimOnActiveUnitWithDeamon(parent, SID_Example, NULL, NULL);
	return true;
#endif

	return false;
}
```

Registration, in `Kernel/Wizardry/PostActionHook/data.event`, inside `gPostActionFuncs` above `//End`:

```
    POIN PostAction_Example
```

Registration, in `Kernel/Wizardry/SkillEffects/MiscSkillEffects.event`, in the PostAction block:

```
#include "PostActionSkills/Example.lyn.event"
```

## Worked examples

- `Kernel/Wizardry/SkillEffects/PostActionSkills/Glorifier.c` : gate on `enemy_defeated`, `SkillListTester`, anim with `NewMuSkillAnimOnActiveUnitWithDeamon(parent, ..., NULL, NULL)`, return `true`. Note: it returns `true` on the skip path too (`:26-30`).
- `Kernel/Wizardry/SkillEffects/PostActionSkills/Heal.c` : `PostAction_BattleActorHeal` (`:10`) and `PostAction_BattleTargetHeal` (`:134`). Computes an amount. Skip path applies it directly with `AddUnitHp` and returns `false` (`:125-128`). Otherwise `CallMapAnim_Heal(parent, ...)` and `return true` (`:130-131`). Returns `false` when nothing to heal (`:119-120`).
- `Kernel/Wizardry/SkillEffects/PostActionSkills/Shakedown.c` : anim then popup. The anim callback `callback2` (`:18-21`) calls `NewPopup_GoldGot(proc, ...)` with `gPostActionCommonBuffer.total_damage_actor`. Started at `:35`, `return true` at `:38`.
- `Kernel/Wizardry/SkillEffects/PostActionSkills/Thunderstorm.c` : event-based effect. `KernelCallEvent(EventScr_CallThunderfxAtPosition, EV_EXEC_CUTSCENE, parent)` at `:133`. Skip path calls `SetThunderstormAoeDamage()` and returns `false` (`:128-131`).

## Gotchas

- `return true` with nothing started still costs a frame: the list stops and resumes next frame (`hook-proc.c:64-66`, `:70-82`). Return `false` unless you started a blocking child.
- `NULL` parent does not block. `CallMapAnim_HealExt` starts on `PROC_TREE_3` when `parent` is `NULL` (`Heal.c:84-86`). `KernelCallEvent` runs inline when `parent` is `NULL` (`event-call.c:28-31`). Pass the hook `parent` through.
- START skip: `CheckKernelHookSkippingFlag()` is true once START was pressed during the hook list (`hook-proc.c:11-14`, `:36-41`). Skip the anim only. The state change must still happen (`Heal.c:125-128`).
- `AlertStance.c` looks wrong. The base `SID_AlertStance` branch (`:46-54`) calls the anim only when `CheckKernelHookSkippingFlag()` is true (`:49-50`), and it passes `SID_AlertStancePlus` as the sid. The `Plus` branch (`:35-43`) uses the inverse check and the correct sid. Do not copy the base branch. Not verified in game.
- Several entries are declared `void` but sit in the `bool` table (`HookProcFunc_t`): `Caltrops.c:7`, `EXPShare.c:7`, `Debilitator.c:12`, `AngerPoint.c:12`, `SealSkills.c:14`, `Hellscape.c:33`. Their return register is undefined, and the runner treats any non-zero value as "started something" (`hook-proc.c:64-66`). Unverified whether this causes a visible problem. New entries should be `bool` and return `false`.
- `Canto.c` is not a hook skill. It is not in `gPostActionFuncs`. It replaces vanilla `TryMakeCantoUnit` and `PlayerPhase_FinishAction` with `LYN_REPLACE_CHECK` (`Kernel/Wizardry/SkillEffects/PostActionSkills/Canto.c:94-95`, `:143-144`), and the entries live in `LynJump.event`. Use it only as an example of a vanilla rewrite.
- The post-action list runs for CPU actions too (`PostActionHook.event:15-16`). Do not assume `gPlaySt.faction` is the player.
- Check the acting unit before reading its state. `gActiveUnit` can be dead or stoned (`Heal.c:18`, `Glorifier.c:24`).
- `NewMuSkillAnimOnActiveUnitWithDeamon` takes no unit argument (`MapAnimSkillMini.c:227`). The anim reads `gActiveUnit` (`MapAnimSkillMini.c:107`, `:122`, `:127`). Set `gActiveUnit` first if you need a different unit (`FreeSpirit.c:68` does this in the End-turn type).
- To refresh the action (the unit acts again; meaning inferred from the flag name, not traced in the engine), the existing pattern sets `gActionDataExpa.refrain_action = true`, calls `EndAllMus()`, then `StartStatusHealEffect(gActiveUnit, parent)` (`Tsuzuku.c:17-26`, `Canto.c:150` for the flag itself).
