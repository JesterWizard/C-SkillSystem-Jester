# End-turn skills

> Text file: `Contents/Texts/Source/texts/Skills_EndTurn.txt`  ·  Code: `Kernel/Wizardry/SkillEffects/EndTurnSkills/`  ·  Hook: `gEndTurnFuncs` in `Kernel/Wizardry/EndTurnHook/data.event`

The chapter-init type (`ChapterInitHooks`) is documented at the end of this file, under "Chapter-init skills".

## What it is

Entries in `gEndTurnFuncs` run when a faction's turn ends: the player's End command and the end of the CPU phase. Units that have acted or not acted can be checked here. The only skill in the list is FreeSpirit, which applies `UNIT_STAT_BUFF_FREESPIRIT` to units that did not act, with an animation.

## How the engine calls it

1. Player phase: the vanilla player-phase proc script is patched at `0x59ACD8` to call `EndTurnHook_PlayerPhase` (`Kernel/Wizardry/EndTurnHook/EndTurnHook.event:8-9`, `PROC_CALL_ROUTINE_2`). That function (`Kernel/Wizardry/EndTurnHook/Source/EndTurnHook.c:35-39`) calls `Proc_StartBlocking(ProcScr_PlayerPhaseEndTurnHook, proc)` and returns `false`.
2. `ProcScr_PlayerPhaseEndTurnHook` (`EndTurnHook.c:12-20`) runs `PROC_YIELD`, `PROC_CALL(EndTurnHook)`, `PROC_YIELD`, then vanilla `PROC_WHILE(DoesBMXFADEExist)`.
3. CPU phase: the vanilla CPU-phase proc script is patched at `0x5A7F20` to call `EndTurnHook_AiPhase` (`EndTurnHook.event:12-13`). `EndTurnHook.c:41-45` starts `ProcScr_AiPhaseEndTurnHook` (`:22-30`), which runs the same hook and then vanilla `AiPhaseCleanup`.
4. `EndTurnHook(ProcPtr proc)` (`EndTurnHook.c:7-10`) calls `KernelStartBlockingHookProc(gpEndTurnFuncs, proc)`. The walker is `HookProc_Main` (`Kernel/Wizardry/KernelLib/Source/hook-proc.c:52-68`). Entry type is `bool (*)(ProcPtr)` (`include/common-chax.h:44`). `true` stops the walk for the frame; `false` continues (`hook-proc.c:64-66`).
5. List (`Kernel/Wizardry/EndTurnHook/data.event:2-6`): `EndTurnSkill_FreeSpirit`, then `CallExternalEndTurnHook` (`Kernel/Wizardry/EndTurnHook/Source/usr-func.c:5-11`, external hook pointer `gpExternalEndTurnHook`), then `WORD 0`.
6. The player's End command: `CommandEffectEndPlayerPhase` (`EndTurnHook.c:49-71`, rewritten with `LYN_REPLACE_CHECK` at `:49`). In real-time battle it returns early (`:58-61`). Under CHAX it does `Proc_Goto(proc, 3)` on the vanilla player-phase proc (`:63-65`). What label 3 leads to was not traced (unverified). The `lynjump` entry is `Kernel/Wizardry/EndTurnHook/Source/EndTurnHook.lyn.event:1-6` and `Source/LynJump.event`.

Block/yield semantics are the same as in the post-action doc: the hook walker blocks on a child started with `Proc_StartBlocking(child, parent)`, where `parent` is the hook argument (`FreeSpirit.c:118`). See [PostAction.md](PostAction.md) for the full explanation.

## Add one: steps

1. Do the common steps in [Common.md](Common.md).
2. Create `Kernel/Wizardry/SkillEffects/EndTurnSkills/<Name>.c` with a non-static `bool EndTurnSkill_<Name>(ProcPtr parent)`. It must be non-static because `data.event` references it by symbol. Return `false` unless you started a blocking proc.
3. Choose the pattern:
   - Immediate effect, no anim: loop over the faction with `FOR_UNITS_ONMAP_FACTION(gPlaySt.faction, unit, { ... })` and apply the state. Return `false`. This is the skip path in `FreeSpirit.c:107-115`.
   - Animated effect: write a `ProcCmd` script like `ProcScr_EndTurnFreeSpirit` (`FreeSpirit.c:90-102`). It sets `gActiveUnit` (`FreeSpirit.c:68`) and calls `NewMuSkillAnimOnActiveUnitWithDeamon(proc, SID, NULL, callback)` (`FreeSpirit.c:74`). The entry point then calls `Proc_StartBlocking(ProcScr_<X>, parent)` and returns `true` (`FreeSpirit.c:118-119`).
4. Check the state you need: `US_HAS_MOVED`, `US_UNSELECTABLE` (`FreeSpirit.c:28`), `US_DEAD`, `US_HIDDEN`, and so on.
5. Register: add `    POIN EndTurnSkill_<Name>` to `gEndTurnFuncs` in `Kernel/Wizardry/EndTurnHook/data.event`, above the `// End` comment (`:4`).
6. Include: add `#include "EndTurnSkills/<Name>.lyn.event"` to `Kernel/Wizardry/SkillEffects/MiscSkillEffects.event`, next to the FreeSpirit include (`:161`).
7. Build and test. Not covered by this doc.

## Template

Adapted from `EndTurnSkill_FreeSpirit` (`Kernel/Wizardry/SkillEffects/EndTurnSkills/FreeSpirit.c:104-123`). The loop and the immediate path (`:107-115`) are the model. The animated tail is shown in a comment and is what FreeSpirit does.

```c
#include "common-chax.h"
#include "debuff.h"
#include "skill-system.h"
#include "kernel-lib.h"
#include "constants/skills.h"

bool EndTurnSkill_Example(ProcPtr parent)
{
#if defined(SID_Example) && (COMMON_SKILL_VALID(SID_Example))
	/* Immediate path: apply state to every unit of the ending faction that has the skill. */
	FOR_UNITS_ONMAP_FACTION(gPlaySt.faction, unit, {
		if (!SkillTester(unit, SID_Example))
			continue;

		if (!(unit->state & (US_HAS_MOVED | US_UNSELECTABLE)))	/* has not acted */
			SetUnitStatDebuff(unit, UNIT_STAT_BUFF_EXAMPLE);	/* placeholder: add enum entry and table entry first */
	})

	/* Animated path (FreeSpirit): replace the loop above with
	 *   Proc_StartBlocking(ProcScr_EndTurnExample, parent);
	 *   return true;
	 * where ProcScr_EndTurnExample sets gActiveUnit and calls
	 * NewMuSkillAnimOnActiveUnitWithDeamon(proc, SID_Example, NULL, callback). */
#endif

	return false;
}
```

Registration, in `Kernel/Wizardry/EndTurnHook/data.event`, inside `gEndTurnFuncs` above `// End`:

```
	POIN EndTurnSkill_Example
```

Registration, in `Kernel/Wizardry/SkillEffects/MiscSkillEffects.event`:

```
#include "EndTurnSkills/Example.lyn.event"
```

## Worked examples

- `Kernel/Wizardry/SkillEffects/EndTurnSkills/FreeSpirit.c` : the only End-turn skill in the list. Shows the proc-based anim (`ProcScr_EndTurnFreeSpirit`, `:90-102`), the per-unit loop with `Proc_Goto` (`:44-83`), the immediate path under `CheckKernelHookSkippingFlag()` (`:107-115`), and the blocking start (`:118-119`).
- `Kernel/Wizardry/SkillEffects/EndTurnSkills/FreeSpirit.c` `CheckHasActed` (`:23-32`) : "has acted" check by state (`US_HAS_MOVED | US_UNSELECTABLE`). The UES bit check is commented out (`:25-26`).

## Gotchas

- Only one skill is registered (`data.event:3`). There is no second example. Copy FreeSpirit for the proc pattern, and the template above for the immediate pattern.
- The list type is `HookProcFunc_t`, `bool (ProcPtr)` (`EndTurnHook.c:5`). The data file has no signature comment, unlike `PostActionHook/data.event:1` and `PrePhaseHook/data.event:1`.
- Set `gActiveUnit` before any anim call. `NewMuSkillAnimOnActiveUnitWithDeamon` takes no unit argument (`include/kernel/skill-system.h:298`, `Kernel/Wizardry/SkillSys/SkillMapAnim/MapAnimSkillMini.c:227`), and the anim reads `gActiveUnit` (`MapAnimSkillMini.c:107`, `:122`, `:127`). FreeSpirit sets it at `FreeSpirit.c:68`.
- The skip path must still apply the state. `FreeSpirit.c:107-115` applies it and returns `false`, so no proc is started and the walker does not block.
- The loop reads `gPlaySt.faction` for unit selection (`FreeSpirit.c:36`, `:48`). The faction is the one whose turn is ending, as inferred from the code. Not traced further.
- Both the player and CPU phase-ends run this list (`EndTurnHook.c:35-45`). Check the faction if your skill should be player-only.
- The End command returns early in real-time battle (`EndTurnHook.c:58-61`). The list does not run on that call. The path that runs it later was not traced (unverified).
- `EndTurnFreeSpirit_End` calls `RemoveMuForActiveUnit(5)` (`FreeSpirit.c:85-88`). Its purpose is not traced. Do not copy it without understanding it.
- `CheckHasActed` is state-based: any unit with `US_HAS_MOVED` or `US_UNSELECTABLE` counts as acted (`FreeSpirit.c:28`). This is FreeSpirit's rule. Other skills may need a different test.

## Chapter-init skills

> Text file: `Contents/Texts/Source/texts/Skills_<Category>.txt` (the category depends on the skill)  ·  Code: `Kernel/Wizardry/SkillEffects/ChapterInitSkills/`  ·  Hook: `ChapterInitHooks` in `Kernel/Wizardry/ChapterInitHook/data.event`

### What it is

Entries in `ChapterInitHooks` run at chapter initialisation, before the vanilla `UndeployEveryone()` (`ChapterInit.c:15`). Skills here usually set stat debuffs at chapter start (Initiative, `Initiative.c:116-123`). Some entries are not skills at all (`InitRandC`, `ResetUnitsExpaSus`, `RealtimeBattle_InitChapter`, and others in the same table).

### How the engine calls it

1. The vanilla pointer at `0x59A254` is replaced with `ChapterInitHook` (`Kernel/Wizardry/ChapterInitHook/ChapterInitHook.event:4-6`, `ORG $59A254 POIN ChapterInitHook`). Which vanilla routine calls it was not traced (unverified).
2. `ChapterInitHook(ProcPtr proc)` (`Kernel/Wizardry/ChapterInitHook/Source/ChapterInit.c:7-16`) walks `gpChapterInitHooks` with `for (i = 0; gpChapterInitHooks[i]; i++)` and calls each entry with `proc` (`:11-12`). The loop ends at a zero entry. After the loop it calls vanilla `UndeployEveryone()` (`:15`).
3. `gpChapterInitHooks` is a pointer to `ChapterInitHooks` (`Kernel/Preload/KernelReloc.event:12`, `gpChapterInitHooks: POIN ChapterInitHooks`).
4. The list (`Kernel/Wizardry/ChapterInitHook/data.event:3-20`) includes `ChapterInit_SetInitiativeStatus` (`:9`) and `ChapterInit_ApplyGrassySurge` (`:13`). It ends with `WORD 0` (`:20`).

Signature: the comment at `data.event:1` says `void (*)(void)`. The runner's typedef is `void (*ChapterInitHookFunc)(ProcPtr proc)` (`ChapterInit.c:3`), and it calls each entry with `proc` (`:12`). Use `(ProcPtr proc)` and return `void`. The Initiative functions are declared `bool` (`Initiative.c:116`, `:125`) and that return value is ignored.

### Template

Adapted from `ChapterInit_SetInitiativeStatus` (`Kernel/Wizardry/SkillEffects/ChapterInitSkills/Initiative.c:116-123`) and its helper `_SetInitiativeStatDebuf` (`:48-53`). The return type is changed from `bool` to `void` to match the typedef in `ChapterInit.c:3`.

static void _Example_SetStatDebuff(struct Unit *unit)

#if defined(SID_Example) && (COMMON_SKILL_VALID(SID_Example))
	if (SkillTester(unit, SID_Example))
		SetUnitStatDebuff(unit, UNIT_STAT_BUFF_EXAMPLE);	/* placeholder: add enum entry and table entry first */

### Worked examples

- `Kernel/Wizardry/SkillEffects/ChapterInitSkills/Initiative.c` : `ChapterInit_SetInitiativeStatus` (`:116-123`) sets the Initiative debuffs for every unit on the map through `FOR_UNITS_ONMAP_ALL` (`include/kernel/kernel-lib.h:423-438`). `ChapterInit_ApplyGrassySurge` (`:125-132`) places grass tiles with `AddGrassTile` (`:44`).
- `Kernel/Wizardry/SkillEffects/ChapterInitSkills/Initiative.c` `PrePhase_TickInitativeSkillStatus` (`:134-168`) is also in the PrePhase list, and clears the same debuffs from `chapterTurnNumber >= 2`. See [PrePhase.md](PrePhase.md).
- `Kernel/Wizardry/Chatlog/Source/Chatlog.c:231` : `ChapterInit_ResetChatlog(void)`, a non-skill entry declared `void (void)`. Shows that entries that ignore the argument are in the same table.

### Gotchas

- The `data.event:1` comment (`void (*)(void)`) disagrees with the runner (`ChapterInit.c:3`, `:12`). The runner passes `proc`. Declare entries with `(ProcPtr proc)` for new code.
- The walker stops at a zero entry (`ChapterInit.c:11`). Keep the `WORD 0` at `data.event:20` at the end of the list.
- The list is shared with non-skill setup (see the list in `data.event:4-19`). Do not reorder existing entries without checking their dependencies. The order of the Initiative entries relative to `ChapterInit_ResetStartMapEffects` and `ChapterInit_ResetSkillStaffTempState` was not traced.
- `Initiative.c` uses a helper that has `#if` inside the function body, not inside `FOR_UNITS_ONMAP_ALL`. Preprocessor directives inside a macro argument are not portable C, so keep the `#if` in a helper, as in the template.
- The chapter-init hook runs before the vanilla `UndeployEveryone()` (`ChapterInit.c:15`). Whether units are on the map at that point for every chapter type was not traced (unverified).
